How I built Drawbridge.

From a hallway gripe to an open-source plugin on Chrome Web Store. The numbered list below is roughly the build sequence — customer, problem, process, design, engineering, result.

customer 01 / 13

I am a vibecoder.

I tell an LLM what to build.

  1. 01I’ve been building games, websites, and apps
  2. 02AI accelerates this process
  3. 03But I inevitably have to tweak the app
  4. 04My process was breaking down with front-end tweaks
+ sizzle reel — my projects
problem 02 / 13

Telling AI what to fix.

Describing what I want to change became taxing.

  1. 01I created screenshots
  2. 02Annotated them with arrows
  3. 03Described the changes
  4. 04But the LLM wouldn’t always get it
+ image — hand annotation
problem 03 / 13

Takes a lot of time.

Required lots of back-and-forth, babysitting changes, and corrections.

  1. 01Uploading those changes one by one
  2. 02Waiting for the results
  3. 03Trying again if the prompt failed
+ video — back-and-forth editing workflow
process 04 / 13

What if I could leave a comment?

And make sure Cursor has all the context it needs.

  1. 01Leave comments “on” the website
  2. 02Provide element context directly to AI
  3. 03Do this from a plugin to keep my existing workflow
  4. 04Manage them like a tasklist
+ reference — figma comment
design 05 / 13

Leave “Figma comments” for Cursor.

A familiar UX pattern with a different recipient.

  1. 01Open the plugin
  2. 02Click an element
  3. 03Leave a comment
  4. 04Save it to the “moat”
  5. 05Info is saved in the backend
+ image — making a comment with drawbridge
design 06 / 13

Draw a rectangle.

Capture multiple objects at once.

  1. 01Using Chrome’s captureVisibleTab
  2. 02Passing a visual reference to the task
  3. 03Mapping the original rectangle back to the UI for reference
  4. 04Migrated to Chrome Side Panel API for clean separation
+ drawing a rectangle to leave a comment
ui / ux · interaction 07 / 13

UI evolution + Side Panel API.

Light/dark, sidebar transitions, and a clean break from CSS isolation.

  1. 01Light/dark modes, sidebar transitions
  2. 02Hit CSS isolation limits
  3. 03Migrated to Chrome Side Panel API for clean separation
+ ui modes + side panel migration
engineering 08 / 13

Context-rich JSON annotations.

Made available by task-driven workflows in markdown.

  1. 01Connects to a local file (security)
  2. 02Spins up task-list.md, task-list.json + screenshots folder
  3. 03Each comment writes to all three: prompt + JSON + screenshot id
  4. 04Workflow instructs Cursor to read the files and update the code
+ markdown prompt · json · screenshots folder
engineering 09 / 13

Inspired workflow.

Developed a method based on AI Dev Tasks.

  1. 01Workflow instructs Cursor to read the task list
  2. 02Reference the JSON + screenshots folder
  3. 03Update the code accordingly
  4. 04Works through all tasks until complete
+ video — cursor processing tasks
result 10 / 13
iteration speed 10×

Faster iteration. One change took 2–3 minutes; now 2–3 minutes for 10 changes.

— same wall clock, ten times the surface area.

1 → 10 changes · per Cursor session · 2026

  3. 03Reviews + issues seeded new ideas for development
  4. 04Learned to manage issues, PRs, and releases
  5. 05Expanded support for Claude Code
+ youtube — AI labs feature
